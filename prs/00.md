## Purpose

Every new test has to be added by hand to one very long line in `package.json`. That is easy to forget, and it also makes every later PR edit the same line and clash with the others. When I checked, two tests that already exist (`cameras` and `map-appearance`) were never being run, and one of them was broken.

## Changes (what you will notice)

Developers only, nothing changes for people using the app.

- `npm test` now finds and runs every test file by itself. Adding a test no longer means editing `package.json`.
- `npm test speed` runs only the tests whose file name contains `speed`.
- The two forgotten tests now run. `cameras` already passed. `map-appearance` had an out-of-date stand-in for the web page and failed; I fixed the test (one added line) and its original checks pass.

## Testing

**Try it yourself, by hand**

1. Run `npm run build && npm test`.
2. Expected: it prints each test's PASS line and ends with `27 test files passed`.
3. Try `npm test camera`. Expected: only the camera test runs.
4. To see it fail properly, add the line `throw new Error('x')` to the top of any file in `tests/`, run `npm test`, and expect `Failed:` with that file's name and a non-zero exit. Then undo it.

**Run the automated checks** (about 10 seconds, no accounts or keys needed)

```sh
git remote add dandycrypto https://github.com/dandycrypto/lapan-malaysia.git   # first time only
git fetch dandycrypto pr/00-test-runner
git switch --detach FETCH_HEAD
npm run build && npm test
```

Expected: the last line reads `27 of 27 test files passed`. Result when I ran it on commit `9666c4a`: **27 of 27 test files passed**.

A combined copy of the whole series (every PR together, not this PR alone) runs at https://lapan-test.dysolvit.com if you would rather look at it on a phone. It may be a little behind the latest commits.

**What I have not tested**

- Not tested on a real iPhone (Safari) or a real Android phone. Everything was checked in desktop Chrome sized like a phone (390 x 844).
- Not tested with real GPS while driving. A recorded drive along a real road was replayed instead.
- Not tested against live TomTom. The route in the replay is a fixed copy, so real routing, traffic and tolls were not exercised.
- Not load tested.
