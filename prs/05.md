## Purpose

The 2D map library (Leaflet) was fetched from a public website (unpkg.com) on every visit. If that site is down, Lapan has no map. It also tells that third party about every Lapan visitor, and forced that address into the browser safety rules.

## Changes (what you will notice)

Lapan now serves its own copy of the same Leaflet 1.9.4 files, unchanged. People notice nothing. The page no longer contacts unpkg.com.

## Testing

**Try it yourself, by hand**

1. Open the app and plan a route. Expected: the map and route draw as usual.
2. In the browser's developer tools, Network tab, reload. Expected: no request goes to `unpkg.com`.
3. `npm test headers` checks the bundled files are byte for byte the official 1.9.4 release (it compares fingerprints) and that the security rules no longer list unpkg.

**Run the automated checks** (about 10 seconds, no accounts or keys needed)

```sh
git remote add dandycrypto https://github.com/dandycrypto/lapan-malaysia.git   # first time only
git fetch dandycrypto pr/05-self-host-leaflet
git switch --detach FETCH_HEAD
npm run build && npm test
```

Expected: the last line reads `31 of 31 test files passed`. Result when I ran it on commit `368d39a`: **31 of 31 test files passed**.

A combined copy of the whole series (every PR together, not this PR alone) runs at https://lapan-test.dysolvit.com if you would rather look at it on a phone. It may be a little behind the latest commits.

**What I have not tested**

- Not tested on a real iPhone (Safari) or a real Android phone. Everything was checked in desktop Chrome sized like a phone (390 x 844).
- Not tested with real GPS while driving. A recorded drive along a real road was replayed instead.
- Not tested against live TomTom. The route in the replay is a fixed copy, so real routing, traffic and tolls were not exercised.
- Not load tested.
